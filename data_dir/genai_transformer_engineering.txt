GENAI ENGINEERING TOPIC 1: TRANSFORMERS, TOKENIZATION, AND INFERENCE MECHANICS
=============================================================================

Modern text-centric generative models are dominated by decoder-only Transformers trained with a next-token prediction objective. From an engineering perspective, the key is to understand the data path from raw text to logits and the computational cost drivers along the way. Inputs are first tokenized into integer IDs using subword tokenization (typically BPE-like or unigram variants). Tokenization choices influence effective context length (more tokens for the same text), latency (more steps), and even error modes (rare strings may fragment into many tokens). Tokenizers also define the model’s vocabulary size V, which controls the output projection size and thus the cost of the final linear layer that maps hidden states to logits.

At the core, a decoder-only Transformer stacks L identical blocks, each containing self-attention and a position-wise feed-forward network (FFN). For a sequence length T and hidden width d_model, the attention sublayer forms queries Q, keys K, and values V via linear projections of the hidden states. The attention weights are computed as softmax(QKᵀ / √d_k) with a causal mask, then applied to V to form a weighted sum per token position. The dominant compute term for attention is O(T² · d_k) due to the QKᵀ matrix, while the FFN is O(T · d_model · d_ff) where d_ff is typically 3–8× d_model. In practice, for long contexts attention can dominate, but for many production settings (moderate T and large d_ff) the FFN is the main FLOP consumer. Engineers should treat both as tunable: attention scaling depends on T, while FFN scaling depends on width and the chosen activation (GELU, SwiGLU, etc.).

The model is trained to minimize cross-entropy loss over the next-token distribution. This training objective produces a conditional language model p(x_t | x_<t), which becomes a generator at inference time by iterative sampling. For deployment, the critical distinction is between “prefill” and “decode.” Prefill ingests the prompt/context of length T and produces K/V tensors for each layer and head; decode then generates one token at a time while reusing cached K/V. Prefill cost scales roughly with T, and decode cost scales with generated length G, but decode is latency-sensitive because it is sequential. The K/V cache size is O(L · H · T · d_head) and frequently dominates memory footprint at large contexts. Systems engineering often involves trading maximum context length and batch size against GPU memory, and it also involves selecting cache data types (FP16/BF16 vs FP8/INT8) to reduce memory bandwidth pressure.

Positional encoding is another practical concern. Absolute position embeddings are simple but constrain extrapolation beyond the trained context window. Modern systems often use relative or rotary embeddings (RoPE) that allow smoother length generalization. From an engineering standpoint, what matters is that the attention mechanism requires some representation of position to break permutation symmetry; the implementation affects numerical stability, compatibility with cache reuse, and potential context extension strategies (for example, RoPE scaling variants). When extending context windows, attention cost and cache memory rise linearly or quadratically depending on architecture; therefore, long-context deployments often incorporate attention optimizations (flash attention kernels, block-sparse attention, sliding window attention) to reduce memory traffic and compute.

The output layer maps hidden state h_t to logits z_t = W_out h_t + b, then softmax converts logits into probabilities. The “sampling policy” is separate from the model: engineers can choose greedy decoding, beam search, nucleus sampling, or constrained decoding. The key technical point is that decoding is a search strategy over token sequences; different strategies trade off determinism, diversity, and computational cost. Beam search expands multiple hypotheses per step and can improve sequence-level likelihood but increases decode-time compute by the beam width; nucleus sampling can reduce degenerate repetitions by limiting the candidate set to tokens whose cumulative probability exceeds a threshold. Regardless of policy, the quality and speed of decoding are heavily influenced by how quickly the runtime can produce logits per token.

Practical Transformer deployment is ultimately about throughput (tokens/sec) and latency (time-to-first-token and time-per-token). Kernel fusion, tensor parallelism, pipeline parallelism, and quantization are the main levers. Flash attention reduces memory reads/writes by computing attention in a tiled manner that avoids materializing large intermediate matrices. Tensor parallelism shards linear layers across devices to fit large models, while pipeline parallelism partitions layers into stages to reduce per-device memory. Quantization (INT8/INT4/FP8) reduces bandwidth and can increase throughput, but it introduces calibration and accuracy considerations and may complicate operator support. A robust engineering mental model is to measure performance separately for prefill and decode, and to map bottlenecks to memory bandwidth, compute utilization, or interconnect overhead.

Finally, many model families incorporate architectural enhancements that are directly relevant to engineers. Grouped-query attention (GQA) reduces the number of key/value heads relative to query heads, shrinking cache size and improving decode speed with minimal quality loss. Mixture-of-Experts (MoE) architectures increase parameter count without proportional compute by routing tokens through a subset of experts, changing scaling behavior and introducing routing, load-balancing, and distributed execution challenges. Understanding these design choices helps engineers anticipate system constraints and select appropriate runtimes and hardware layouts. In short, Transformer engineering is the study of how tokenization, attention/FFN compute, cache memory, and parallel execution interact to determine real-world performance.
